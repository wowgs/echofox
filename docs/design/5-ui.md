# 5. UI

Интерфейс приложения: строка меню, окно настроек, сочетания клавиш и то, как устроены настройки, чтобы их было легко переносить и добавлять. Требования — FR-10 — FR-13, FR-2, NFR-5 во вкладке [Requirements](2-requirements.md). Где UI стоит в архитектуре — [HLD](4-hld.md#слои).

## Принципы

- Диктовка — сочетанием клавиш, не из меню.
- В строке меню — только то, что пользователь трогает часто. Всё остальное — в окне настроек.
- UI ничего не решает сам: читает и пишет конфиг и спрашивает сервер. Сервер — бэкенд, UI его вызывает.
- Каждая настройка описана один раз; где она показана, решает одно поле (см. «Как устроены настройки»).

## Строка меню

**Значок** показывает состояние диктовки: ожидание, идёт запись (красный микрофон), ждём модель, проблема (перечёркнутый микрофон). Так сделано сейчас (`macos/Sources/LocalVoice/MenuBar.swift`).

**Меню**, сверху вниз:

1. **Разрешения.** Одна строка с подменю, по пункту на разрешение: «Универсальный доступ», «Микрофон». Выданное разрешение — серый неактивный пункт с галочкой. Невыданное — активный пункт; нажатие открывает нужное место в системных настройках. Строку видно и тогда, когда всё выдано.
    - Сейчас приложение открывает нужное место по адресу `x-apple.systempreferences:com.apple.preference.security?<раздел>` (`Permissions.swift`).
    - Предложение: в заголовке строки — итог, например «Разрешения: всё в порядке» или «Разрешения: нужен микрофон».
2. **Микрофон и громкость** (предложение). Подменю выбора микрофона и ползунок громкости входа. Наушники то подключаются, то нет, и уровень сбивается — это трогают часто. Предложение: рядом с ползунком — живой уровень сигнала.
3. **Label Recordings…** (предложение). Пока пользователь размечает, это частое действие. Когда разметка не нужна, пункт переносится в окно — одним полем (см. ниже).
4. **Settings… (⌘,)** — окно настроек.
5. **Quit Local Voice.**

Сейчас в меню есть Model, Language и Adapters; они уходят в окно.

## Сочетания клавиш

| Действие | Что делает | Сейчас |
|---|---|---|
| Диктовка | Нажатие начинает запись, следующее — кончает; текст вставляется в поле, где был курсор при старте (FR-1). | одиночное нажатие правого ⌥ (`TapLogic.swift`) |
| Приватная диктовка | То же, но без чтения экрана (FR-2): приложение берёт только поле ввода, куда вставить текст; снимок фокуса на сервер не уходит, адаптеры не вызываются, контекста нет. | нет |

Оба сочетания настраиваются на странице General. Предложение: окно проверяет, не занято ли сочетание другим действием Local Voice; занято ли оно системой или другим приложением — открытый вопрос: надёжного способа узнать это мы не проверяли.

Что видно во время приватной диктовки — предложение: тот же значок записи с отличием (например, другой символ), чтобы было понятно, что экран не читается.

## Окно настроек

Отдельное окно со страницами в боковой панели. Предложение по страницам:

| Страница | Что на ней | Требования |
|---|---|---|
| General | Сочетания клавиш, остановка после тишины, язык речи, запуск при входе в систему | FR-12, FR-1, FR-2 |
| Microphone | Микрофон, громкость, уровень сигнала, пробная запись | FR-1 |
| Model | Модель из каталога, установка и удаление, сколько памяти занимает, выгружать ли в простое | FR-7, FR-8, NFR-7 |
| Recognition | Промпт и пометки по языкам; сэмплинг (`temperature`, `topK`, `topP`, `seed`); резка (`pieceSeconds`, `cutSearchSeconds`, `cutWhileSpeaking`, `minLastPieceSeconds`); речь (`minSpeechSeconds`, `maxCharsPerSpeechSecond`, `thresholdDb`); слова-паразиты; лимиты ответа | FR-9, FR-3, FR-4 |
| Adapters | Список, вкл/выкл, что каждый читает (из манифеста), бюджеты контекста (`chatHistoryTokenBudget`, `chatTermsTokenBudget`, `chatHistoryMessages`) | FR-5, FR-6 |
| Recordings & labels | Сохранять ли записи, папка, занятое место; сколько минут размечено; потом — запуск дообучения | FR-16, FR-17, FR-18 |
| History | Последние тексты: скопировать, вставить ещё раз | FR-19 |
| Diagnostics | Сервер, модель в памяти, последние ошибки, журналы | FR-20 |

У каждого поля — значение по умолчанию рядом и кнопка «сбросить» (предложение).

## Как устроены настройки

Цель — NFR-5: настройку легко перенести между меню и окном и легко добавить. Ниже — предложение.

![Описание настроек приходит от сервера и из приложения, раскладка — из приложения; один построитель рисует и меню, и окно](img/5-ui-settings.svg)

Описание настройки и её место на экране хранятся раздельно, а меню и окно строит один построитель; оранжевым — сервер, синим — приложение, серым — файл конфига, пунктир — запись значений; масштаба у схемы нет.

**Описание** — что это за настройка. Его даёт тот, кто её понимает:

- **Настройки сервера** — сервер, из своей таблицы (`server/tuning.py`, `KNOBS`, и `server/settings.py`, `SETTINGS`). Он отдаёт их в ответе `info` (схема ниже). Новая ручка сервера появляется в окне без правки приложения.
- **Настройки приложения** (сочетания клавиш, микрофон, громкость, разметка) — приложение, из такой же таблицы в Swift.

**Раскладка** — где настройка показана: в меню (порядок) или на странице окна (страница, раздел, порядок). Раскладка живёт только в приложении: это вопрос интерфейса, сервер о нём не знает. Перенести настройку — поменять её строку в раскладке. Настройка, которой в раскладке нет, попадает на свою страницу в раздел «Другое», чтобы новое никогда не терялось.

**Запись.** Окно пишет в `~/.local-voice/config.json` так же, как меню сейчас: меняет одно значение и сохраняет разметку файла (`JSONEdit.swift`). Сервер сам подхватывает изменения конфига (так работает сейчас). Неверное значение сервер сейчас пишет в журнал и не применяет: действует значение по умолчанию (`server/settings.py`, `file_settings`). Предложение: ошибку видно рядом с полем и на странице Diagnostics.

### Схема описания настройки в ответе `info`

Сейчас `info` отдаёт модели, языки и адаптеры (протокол — в README). Предложение: добавить поле `settings`, список описаний.

| Поле | Тип | Что значит |
|---|---|---|
| `key` | строка | Имя в конфиге, например `pieceSeconds` |
| `group` | строка | Смысловая группа: `cutting`, `sampling`, `speech`, `context`, `output`, `recording` |
| `kind` | `number`, `integer`, `boolean`, `string`, `choice` | Тип значения |
| `min`, `max` | число | Диапазон, для чисел |
| `choices` | список строк | Варианты, для `choice` |
| `default` | значение | Значение по умолчанию |
| `value` | значение | Текущее значение, если оно задано в конфиге |
| `where` | список: `server`, `model`, `adapter`, `client` | Где её можно задать: на весь сервер, для модели, для адаптера, в запросе |
| `help` | строка | Одна фраза: что делает |

Что для этого меняется в сервере: сейчас диапазон ручки — функция в коде (`Knob.ok`), а не данные. Для схемы диапазон нужен как данные: `min`, `max`, `choices`.

## Открытые вопросы

- Сохранять ли записи приватной диктовки (FR-2, FR-16).
- Как узнать, что сочетание клавиш занято системой или другим приложением.
- Оставлять ли в меню «Микрофон» и «Label Recordings…» (предложения выше).
