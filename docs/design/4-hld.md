# Архитектура

Приложение записывает звук и вставляет текст. Сервер готовит аудио и контекст. Отдельный `llama-server` запускает модель. Состояние описания — 25 октября 2026.

![Путь диктовки: приложение, сервер, адаптеры и локальная модель.](img/4-hld.svg)

Синим показано приложение, оранжевым — сервер, зелёным — модель. Стрелки показывают путь данных; размеры блоков не обозначают время или расход памяти.

Требования FR и NFR определены в [требованиях](2-requirements.md). Точные форматы и команды находятся в [справочнике](../README.md).

## Процессы

- **Mac-приложение:** интерфейс, клавиши, микрофон, Accessibility и вставка. Разрешения macOS выдаются этому процессу.
- **Сервер диктовки:** агент launchd; принимает аудио, выбирает адаптер, готовит запросы и сохраняет результаты.
- **llama-server:** агент выбранной модели. В памяти находится только выбранная модель.

В сборке для распространения сервер, Python и `llama-server` находятся внутри `.app`. Модель скачивается отдельно. Обновления через Sparkle пока запланированы; устройство пакета описано в [распространении](7-distribution.md).

## Почему аудио делится на части

Модель принимает не больше 30 секунд за запрос. Сервер отправляет завершённые части, пока человек ещё говорит, и обрабатывает остаток после остановки. Два слота модели позволяют распознавать две части одновременно.

Silero VAD определяет наличие речи. Уровень громкости помогает выбрать тихое место для разреза, но не заменяет VAD. Порог речи и ограничение длины ответа защищают от выдуманного текста на тишине и бесконечной генерации.

Значения порогов и алгоритм нарезки описаны один раз — в [справочнике сервера](../reference/1-server.md).

## Настройки: у каждой свой хозяин

Хозяин — компонент, который определяет смысл настройки и её значение по умолчанию. Пользовательская правка хранится у этого же компонента.

| Компонент | Источник значений по умолчанию | Правки пользователя |
|---|---|---|
| Адаптер | `adapter.json`, поле `context` | `adapters.<имя>` |
| Модель | `server/catalog.json` | `models.<имя>.prompt`, `models.<имя>.options` |
| Язык | `server/languages.json` | `languages.<код>` |
| Сервер | `server/tuning.py` | `server` |
| Приложение | Swift-код | Верхний уровень конфига |

Приоритет: параметры экспериментального запроса → правки пользователя → значения компонента по умолчанию. Ограничения модели, например максимальная длина аудио, действуют независимо от правок.

Обычные параметры видны сразу, тонкая настройка находится в Advanced. Защитные константы не показываются как настройки. Приложение не отправляет экспериментальные переопределения; ими пользуется тестовый клиент.

Шаблон промпта принадлежит модели, языковые примечания — языку. Замена шаблона не отменяет добавление языковых примечаний. Адаптер выключается через `enabled`, а не нулевым бюджетом.

Формат конфига сейчас имеет версию 7; миграции выполняет сервер. История каждой миграции остаётся в `server/settings.py`, а актуальные ключи — в [справочнике конфигурации](../reference/2-config.md).

## Разговор на экране

1. Приложение делает снимок фокуса в начале обычной диктовки: приложение, окно, элемент ввода, метаданные родителей, веб-область и рабочие папки процессов. Значения полей ввода исключаются.
2. Сервер спрашивает включённые адаптеры, подходит ли им этот снимок. Выбирается самый уверенный ответ.
3. Выбранный адаптер ищет точную сессию. Если найти её нельзя, диктовка идёт без контекста.

Дополнительные данные экрана собираются только по запросу включённого адаптера: строки списков окна (сообщения Telegram) или дерево страницы (сообщения чата Claude Desktop, которые не лежат в списках). При приватной диктовке снимок контекста не отправляется и адаптеры не вызываются.

### Что показали первые замеры

15 октября 2026 в Claude Desktop 2.37337.1 удалось связать URL Code-вкладки с локальной записью сессии. Без `AXManualAccessibility` поле не было видно; после включения оно появлялось примерно через 2,1 секунды в трёх прогонах. Поэтому доступ включается заранее для приложений, которым он нужен.

У Telegram заголовок окна давал имя чата, а список над полем — сообщения. 25 октября 2026 в Claude Desktop 3.6556.2 у обычного чата не нашлось локального транскрипта: только кэш веб-приложения в IndexedDB. Зато дерево Accessibility страницы размечает каждое сообщение группой «Message N of M»; чат из 4 сообщений дал 532 элемента, снимок занял 93 мс (один прогон). Ghostty отдавал рабочую папку через `AXDocument`, Chrome — URL вкладки. Надёжную позицию курсора получить не удалось; VS Code в том замере не проверялся.

Это наблюдения конкретных версий. Текущий алгоритм сопоставления описан в [справочнике контекста](../reference/3-context.md).

## Индикатор записи (FR-14)

План: персонаж поверх окна диктовки, который не забирает фокус и пропускает клики. Сейчас есть только прототип прозрачного рендера `macos/prototypes/transparent-realitykit-overlay.swift`.

В одном прогоне 18 октября на M5 с macOS 27 проверена связка RealityRenderer → Metal-текстура → прозрачный CAMetalLayer в NSPanel. Для прототипа используется API macOS 15+, поэтому совместимость с минимальной версией приложения нужно решить отдельно.

Ещё не реализованы модель USDZ с анимациями, реакция на громкость, следование за окном и статичный режим при включённом «Уменьшить движение». Нужно проверить тени, сглаженные края и нагрузку GPU.
