# Сборка и распространение

EchoFox собирается в один `.dmg` без модели. Внутри — приложение, сервер и все зависимости. Модель пользователь скачивает отдельно при первом запуске.

Состояние на 25 октября 2026: упаковка и механизм загрузки реализованы; опубликованных релизов ещё нет. Полная установка на чистом Mac и публичный выпуск требуют проверки. Команды разработчика — в [руководстве по сборке](../reference/7-development.md#build-a-distributable-app).

## Почему модель скачивается отдельно

Размер модели — несколько гигабайт, и её не нужно повторно скачивать при каждом обновлении приложения. Q4_0 и Q8_0 — варианты одной модели в интерфейсе, а не отдельные сборки приложения. Общий аудиопроектор хранится один раз.

Репозиторий пока приватный. Его открытие и публичный выпуск — отдельные решения.

## Что входит в пакет

| Путь внутри `EchoFox.app/Contents` | Содержимое |
|---|---|
| `MacOS/EchoFox` | Mac-приложение. |
| `Resources/server/` | Сервер, встроенные адаптеры и Silero VAD. |
| `Resources/python/` | Python 3.14 и зависимости сервера. |
| `Resources/llama/` | `llama-server`, собранный с Metal, и его библиотеки. |

Версии закреплены в `macos/pins.sh`. Сборка проверяет, что пакет не зависит от библиотек Homebrew. При запуске приложение записывает агент launchd для собственного сервера. Раннее предложение использовать SMAppService не было выбрано.

Локальная проверка 25 октября: пакет около 217 МБ; стек из пакета распознал 49-секундную запись на тестовом сервере без внешних соединений. Это не проверка установки на другом Mac.

### Установщик

DMG устроен как у Ghostty, Chrome и Telegram (их образы на этом Mac, 26 октября): в окне приложение, ссылка на `/Applications`, фон со стрелкой и подписью «Drag EchoFox to Applications», иконка тома — иконка приложения. Окно собирает dmgbuild 1.6.7 (MIT): он пишет `.DS_Store` сам, без Finder, поэтому работает и на раннере без экрана. Он ставится в отдельное окружение `macos/.cache/dmgtools` с версиями и SHA-256 из `macos/dmg/requirements.txt`. Настройки окна — `macos/dmg/settings.py`, фон — `macos/dmg/background.svg`, из которого сделан `background.tiff` в 1x и 2x.

Сжатие выбрано по замеру 26 октября на M5: один и тот же пакет, распаковка — лучшее из трёх копирований приложения из смонтированного образа.

| Формат | Размер | Распаковка |
|---|---|---|
| UDZO (zlib), как было через `hdiutil create` | 115,4 МБ | — |
| UDZO (zlib), `hdiutil convert` | 79,0 МБ | 1,35 с |
| ULFO (lzfse) | 69,0 МБ | 1,20 с |
| ULMO (lzma) | 53,3 МБ | 2,79 с |
| UDBZ (bzip2) | 65,0 МБ | 4,53 с |

Выбран ULMO: самый маленький образ, а лишние полторы секунды распаковки малы рядом с загрузкой модели; нужен macOS 10.15 или новее. DMG из dmgbuild с ULMO вышел 58,8 МБ: в пакете к тому времени добавилась иконка `Assets.car`.

## Каталог и хранение моделей

`server/catalog.json` задаёт варианты, имена файлов, закреплённую ревизию источника, размеры и SHA-256. Точные значения должны храниться там, а не копироваться в проектный документ.

Источник текущей модели — `ggml-org/gemma-4-E4B-it-GGUF` на Hugging Face. Файлы лежат в `~/Library/Application Support/EchoFox/models/gemma-4-E4B-it-GGUF/`; корневую папку меняет `server.modelsFolder`.

Конфиг модели ссылается на каталог и может выбирать `variant`. При отсутствии варианта используется значение каталога по умолчанию. Сервер строит аргументы и агент `llama-server`; изменение активного варианта применяется после текущей записи.

## Скачивание

Сервер, а не окно приложения, управляет загрузкой:

- продолжает работу после закрытия окна и показывает прогресс подключившимся клиентам;
- возобновляет частичную загрузку через HTTP Range;
- проверяет размер и SHA-256 перед переименованием временного файла;
- не удаляет общие файлы, нужные другому скачанному варианту;
- не позволяет удалить активный вариант.

Команды и ответы описаны в [протоколе](../reference/6-protocol.md#download-a-model).

Первое окно предлагает вариант по памяти Mac: Q4_0 при 16 ГБ, Q8_0 при 24 ГБ и более. Оценки памяти приблизительные. Один прогон Q4_0 распознал 15,7 секунды аудио за 2,89 секунды; это не систематическое сравнение качества или скорости.

Окно загрузки показывает скорость за последние 5 секунд и оставшееся время (`TransferRate` в приложении). Сервер для этого ничего нового не шлёт: хватает прогресса раз в 0,5 секунды.

Загрузка идёт в одно соединение на файл. Замер 26 октября (этот Mac, домашний канал, файл Q4_0 с Hugging Face, по 192 МБ на попытку, свой участок файла на каждую попытку, 3 круга в случайном порядке): одно соединение — 73,4, 78,8 и 71,7 МБ/с; четыре — 64,4, 70,3 и 75,8 МБ/с; восемь — 60,5, 61,8 и 78,2 МБ/с. Выигрыша от нескольких соединений не измерено, поэтому загрузка осталась в одно соединение. На другом канале результат может быть другим; это не проверялось.

Тесты загрузки используют локальный HTTP-сервер. Полная загрузка гигабайтных файлов и весь сценарий первого запуска на чистом Mac ещё не проверены.

## CI на GitHub Actions

| Workflow | Когда запускается | Результат |
|---|---|---|
| `tests.yml` | Вручную или вызовом из release workflow | Проверки Python-сервера и Swift-приложения. |
| `release.yml` | Вручную или при push тега `v*` | Сначала проверки, затем сборка DMG. |

**Обычный push ветки не запускает эти workflows.** Запуск по тегу публикует GitHub Release; ручной запуск сохраняет DMG как артефакт на 14 дней.

При наличии секретов Developer ID и App Store Connect сборка подписывает приложение, отправляет DMG на нотаризацию и прикрепляет результат. Без секретов используется ad hoc подпись только для проверки. Список секретов находится в начале `.github/workflows/release.yml`.

### Нотаризация без ожидания

Apple проверяет заявку от минут до суток и дольше: у новых команд на форумах Apple в 2026 году сообщали о 17–24 часах и до 4 дней. Первая заявка EchoFox 25 октября провисела больше 40 минут, раннер ждал её и тратил квоту. Поэтому раннер Apple не ждёт: выпуск состоит из двух запусков, а второй запускает уведомление Apple.

1. **`release.yml`** проверяет, собирает и подписывает DMG, отправляет его в Apple командой `notarytool submit --webhook <адрес ретранслятора>` и сохраняет артефакт `EchoFox-notarizing-<id заявки>`: подписанный DMG и `release.json` (`submission`, `ref`, `refType`, `sha`, `run`). Запуск на этом заканчивается.
2. **Apple** по окончании проверки отправляет POST на адрес ретранслятора. Формат уведомления Apple не документирует. По стороннему описанию это `{"signature", "cert_chain", "payload"}`, где `payload` — JSON-строка с `submission_id`, `team_id` и `event: "processing-complete"`.
3. **Ретранслятор** — Cloudflare Worker `echofox-notary` (`ci/notary-relay/`). Он берёт из уведомления `submission_id`, проверяет, что это UUID, а `team_id`, если он есть, совпадает с командой EchoFox. Затем запускает `staple.yml` через `POST /repos/wowgs/echofox/actions/workflows/staple.yml/dispatches` с `{"ref": "master", "inputs": {"submission": <id>}}`. Токен GitHub хранится секретом Worker: fine-grained, только репозиторий `wowgs/echofox`, право Actions: write. Право Contents: write, которое требует `repository_dispatch`, разрешало бы и пуш кода, поэтому он не используется.
4. **`staple.yml`** запускается от ретранслятора или вручную с ID заявки. Он находит артефакт заявки, спрашивает статус у Apple (`notarytool info`) и при `Accepted` прикрепляет результат (`stapler staple`), проверяет его (`stapler validate`, `spctl`) и публикует: для тега — GitHub Release, иначе — артефакт `EchoFox-dmg` на 14 дней. При `In Progress` он завершается с ошибкой без публикации, при `Invalid` печатает журнал Apple (`notarytool log`). Ключ подписи Developer ID ему не нужен.

Поддельный запрос на ретранслятор может только запустить `staple.yml`, а тот всё равно сверяет статус у Apple. Если уведомление не придёт, `staple.yml` запускается вручную. ID заявки виден в журнале `release.yml` и в `notarytool history`.

Проверки на GitHub прошли 25 октября за 1 минуту 27 секунд. Это подтверждает запуск тестов, но не готовность подписанного выпуска. Автообновления через Sparkle остаются планом.

## Телеметрия

Локальная проверка 25 октября обнаружила внешние соединения onnxruntime с телеметрией Microsoft. В `server/vad.py` она отключена до загрузки библиотеки через `ORT_DISABLE_TELEMETRY=1` и `disable_telemetry_events()`.

С отключением телеметрии у проверенного стека во время распознавания наблюдались только локальные соединения. `llama-server` собран без OpenSSL и curl и запускается с `--offline --no-webui`. Загрузка модели остаётся явным внешним запросом.

Предложение для будущей проверки выпуска: запускать пакет на тестовой записи и проверять отсутствие неожиданных внешних соединений. Это пока не реализованный шаг CI.

## Проверить перед выпуском

- Установка, разрешения, регистрация launchd и перезапуск на чистом Mac.
- Полная загрузка модели с источника и восстановление после обрыва.
- Подпись, нотаризация и запуск всех вложенных компонентов.
- Совместимость со старыми версиями macOS: код нацелен на macOS 13, проверен на macOS 27.
- Условия использования и распространения модели Gemma.
- Качество, скорость и память Q4_0 против Q8_0 на одном размеченном наборе.

## Открытые вопросы

Нужны ли зеркало моделей, вариант аудиопроектора Q8_0 и использование MTP-файлов? Их пользу ещё нужно измерить. Автообновления и название публичного продукта также требуют отдельных решений.
