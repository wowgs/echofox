# 7. Distribution

Как Local Voice попадает на чужой Мак: что лежит в пакете, откуда берётся модель, как сборку делает GitHub Actions. Состояние на 2026-10-25. Требования — [FR-8 и FR-21](2-requirements.md#модель), архитектура — [HLD](4-hld.md#процессы).

## Решения

- Раздаётся один `.dmg` только с приложением, без модели.
- Модель скачивается при первом запуске. Квантизацию выбирает пользователь в приложении: Q4_0 или Q8_0 той же Gemma 4 E4B. Это выбор в приложении, а не отдельные сборки.
- Сборка для раздачи подписывается сертификатом Developer ID и нотаризуется у Apple (Apple Developer Program, $99 в год).
- Репозиторий пока приватный: его релизы видят только участники. Открыть его — отдельный шаг позже.

## Почему так

- Файл в GitHub Releases не может быть больше 2 ГиБ (несколько источников, среди них [обсуждение GitHub #61733](https://github.com/orgs/community/discussions/61733)). `.dmg` с моделью вышел бы около 5,6 ГБ с Q4_0 и около 9 ГБ с Q8_0.
- У обычного раннера GitHub на macOS (arm64, M1) 3 ядра, 7 ГБ памяти и 14 ГБ диска ([документация GitHub](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)). Сборка с Q8_0 держала бы на диске файлы модели (9 ГБ) и образ почти того же размера: веса почти не сжимаются. Это оценка, не замер.
- Без модели пакет не надо перекачивать при каждом обновлении приложения.

## Код и квантизация

Проверено поиском по коду (2026-10-25): к квантизации привязан только путь по умолчанию в `server/llama_launchd.sh` (`gemma-4-E4B-it-Q8_0.gguf`). Каталог, сервер и приложение квантизацию не знают. Предел длины текста (`maxTokensPerSpeechSecond`) считается в токенах, а токенизатор у Q4_0 и Q8_0 один.

Не измерено: качество распознавания, скорость и память на Q4_0. Оценка памяти: около 6,5 ГиБ против 9,7 ГиБ у Q8_0 (размер файла Q4_0 плюс собственная память `llama-server`, замеренная на Q8_0).

## Что внутри пакета (предложение)

| Путь в `LocalVoice.app/Contents` | Что |
|---|---|
| `MacOS/LocalVoice` | Приложение. |
| `Resources/server/` | Код сервера диктовки, плагины, `vad/silero_vad.onnx`. |
| `Resources/python/` | Python со своими пакетами (`server/requirements.txt`), без системного Python и Homebrew. Например, сборка python-build-standalone (известна по памяти). |
| `Resources/llama/` | `llama-server` и его библиотеки, собранные с Metal из закреплённого коммита llama.cpp. Сейчас — 0.6.0, build 11429, коммит `d81235049`. |
| `Library/LaunchAgents/` | Агенты сервера диктовки и `llama-server`. Приложение регистрирует их само, через `SMAppService` (macOS 13+, по памяти). |

Модели — вне пакета: `~/Library/Application Support/Local Voice/models/<каталог>/<вариант>/`.

## Модели в каталоге (предложение)

Запись модели в `server/catalog.json` получает варианты — по одному на квантизацию:

```json
"gemma-4-e4b": {
  "name": "Gemma 4 E4B",
  "variants": {
    "q4_0": {"files": [{"role": "model", "url": "…", "bytes": 4590807392, "sha256": "…"},
                       {"role": "mmproj", "url": "…", "bytes": 991552256, "sha256": "…"}]},
    "q8_0": {"files": [{"role": "model", "url": "…", "bytes": 8031242688, "sha256": "…"},
                       {"role": "mmproj", "url": "…", "bytes": 991552256, "sha256": "…"}]}
  },
  …
}
```

- `url` указывает на файл Hugging Face в закреплённой ревизии (`ggml-org/gemma-4-E4B-it-GGUF`), чтобы файл не сменился под тем же именем.
- Запись модели в конфиге называет вариант: `"models": {"<имя>": {"catalog": "gemma-4-e4b", "variant": "q4_0", …}}`. Путь к файлам сервер берёт отсюда, а не из аргументов скрипта. Это версия 8 конфига.
- Размеры файлов — с диска этого Мака (2026-10-25); sha256 и ревизию запишем при настройке.

## Скачивание (предложение)

По [HLD](4-hld.md) моделями владеет сервер: у него служебные команды «каталог, установить, удалить, состояние». Приложение их вызывает и показывает прогресс.

1. При первом запуске приложение показывает варианты: размер на диске, память, скорость. У Q8_0 — замеры, у Q4_0 — оценки, пока нет замеров.
2. Сервер качает файлы с докачкой (HTTP Range) и проверяет sha256.
3. Сервер записывает модель в конфиг и запускает её `llama-server`.

Сообщения протокола для этого появятся в [Reference: protocol](../reference/6-protocol.md) до кода.

## CI на GitHub Actions (предложение)

Два процесса:

- **На каждый push** — тесты: `python -m unittest discover -s server` и `swift run lv-tests`. Модель не нужна, хватит обычного раннера `macos-26`.
- **На тег `v*`** — выпуск:
  1. Собрать `llama-server` с Metal из закреплённого коммита.
  2. Положить Python с пакетами, код сервера и приложение в `LocalVoice.app`.
  3. Подписать каждый исполняемый файл и библиотеку изнутри наружу сертификатом Developer ID, с усиленным рантаймом и правом на микрофон.
  4. Собрать `.dmg` (`hdiutil`), отправить на нотаризацию (`notarytool submit --wait`), прикрепить результат (`stapler`).
  5. Выложить `.dmg` в GitHub Release.

Секреты в GitHub: сертификат Developer ID (`.p12` в base64) и его пароль, ключ App Store Connect API для `notarytool` (ключ, его ID, ID издателя).

Минуты macOS-раннеров в приватном репозитории тратятся из бесплатной квоты, а сверх неё оплачиваются. Сколько это стоит, не проверено.

## Порядок работ (предложение)

1. Варианты модели в каталоге и в конфиге (версия 8). После этого Q4_0 можно включить на этом Маке и замерить.
2. Команды сервера «каталог, установить, удалить, состояние» и скачивание.
3. Сборка самодостаточного `LocalVoice.app` (`macos/build-app.sh`): сервер, Python и `llama-server` внутри.
4. Окно первого запуска в приложении.
5. CI: тесты на push, выпуск на тег. Подпись и нотаризация — когда будет Developer ID.

## Открытые вопросы

- Откуда раздавать файлы модели: прямо с Hugging Face (чужой репозиторий, может измениться) или с зеркала (например, Cloudflare R2 на wowgs.uk).
- Только Apple Silicon или ещё Intel. Предложение: только Apple Silicon — llama.cpp на Metal нужен GPU Apple.
- Самая старая версия macOS. Код собирается для macOS 13, проверен только на macOS 27.

## Проверить при настройке

- Регистрирует ли `SMAppService` агенты из пакета так, как нужно серверу: запуск при входе, перезапуск после сбоя.
- Работает ли onnxruntime (Silero VAD) под усиленным рантаймом без лишних прав.
- Влезает ли сборка без модели в диск и время обычного раннера.
- Сколько длится нотаризация пакета с Python и `llama-server`.
