# Требования к продукту

Это целевое поведение EchoFox, а не список уже выпущенных функций. Текущая работа описана в [справочнике](../README.md), незавершённые задачи — в [плане](../ideas.md).

Номера FR и NFR сохранены для ссылок из архитектуры и обсуждений. История диктовок, маскот, LoRA и Sparkle ещё не реализованы. Предложенные требования требуют отдельного решения о включении в первую публичную версию.

## Диктовка

- **FR-1. Диктовка в поле ввода.** Клавиша начинает и завершает запись. При получении результата приложение использует текущее поле ввода, затем исходное поле; если вставить нельзя, сохраняет текст в буфере обмена.
- **FR-2. Приватная диктовка.** Отдельная клавиша. Приложение определяет поле для вставки, но не отправляет снимок контекста. Адаптеры не вызываются; аудио и текст не сохраняются в записях, текст не попадает в журналы.
- **FR-3. Распознавание по ходу речи.** Завершённые части записи обрабатываются до остановки, чтобы сократить оставшееся ожидание.
- **FR-4. Защита от лишнего текста.** Части без речи не отправляются модели. Ответ, достигший защитного лимита длины, отбрасывается.

## Контекст

- **FR-5. Необязательные адаптеры.** Адаптер находит текущий разговор и готовит контекст. Без подходящего включённого адаптера работает обычная диктовка.
- **FR-6. Управление адаптерами.** В настройках видны доступные адаптеры, состояние, источники данных и параметры контекста. Пользовательские значения заменяют значения из манифеста конкретного адаптера.

## Модель

- **FR-7. Локальное распознавание.** Выбранная модель из каталога работает на Mac.
- **FR-8. Установка из приложения.** Сервер устанавливается вместе с приложением; модель скачивается с показом прогресса. Ненужный вариант можно удалить.
- **FR-9. Настройка распознавания.** Модель, промпт, язык и предел записи доступны сразу. Сэмплинг и бюджеты контекста находятся в Advanced. Защитные пороги и параметры нарезки остаются константами реализации.

## Интерфейс

- **FR-10. Короткое меню.** Разрешения, пока они не выданы; микрофон и громкость; разметка; настройки; выход. Значок показывает состояние.
- **FR-11. Окно настроек.** Остальные параметры собраны на отдельных страницах.
- **FR-12. Настраиваемые клавиши.** Отдельные клавиши обычной и приватной диктовки.
- **FR-13. Разрешения.** Невыданное разрешение открывает нужную страницу macOS; выданное показывается неактивной галочкой. Когда всё разрешено, строка исчезает.
- **FR-14. Маскот — запланировано.** Прозрачный анимированный индикатор поверх окна диктовки; значок меню остаётся.
- **FR-15. Первый запуск — предложение.** Последовательно объяснить и запросить разрешения, проверить сервер и модель. Окно выбора модели уже есть; весь сценарий на чистом Mac ещё требует проверки.

## Записи и данные

- **FR-16. Сохранение записей.** Обычная диктовка сохраняет аудио, текст и использованный контекст. Сохранение можно отключить; приватная диктовка не сохраняется. Показ занятого места остаётся предложением.
- **FR-17. Разметка.** Неразмеченные части показываются в случайном порядке. Эталон — текст, который пользователь хотел написать: без запинок и повторов.
- **FR-18. Дообучение — запланировано.** Обучение на проверенных записях пользователя на его Mac; [отдельный проект](../lora-training/1-idea.md).
- **FR-19. История — предложение.** Просмотр последних результатов, повторное копирование и вставка. Нужно определить поведение при отключённом сохранении; приватные диктовки не должны появляться в истории.

## Система

- **FR-20. Диагностика.** Состояние сервера, выбранная модель и ошибки. Расширенный показ памяти и состояния остаётся предложением.
- **FR-21. Обновления — запланировано.** Обновлять приложение, сервер и каталог без терминала через Sparkle.

## Нефункциональные требования

- **NFR-1. Приватность.** Аудио и распознанный текст обрабатываются локально.
- **NFR-2. Готовность к распространению.** Для публичной версии установка и использование не требуют терминала.
- **NFR-3. Расширяемость адаптеров.** Новый плагин добавляется без логики конкретного поставщика в ядре.
- **NFR-4. Минимальный снимок.** Метаданные фокуса не содержат значений полей ввода и буфера терминала. Дополнительный экранный контент собирается только для включённых адаптеров, заявивших его в манифесте. Миграция конфига не включает такие адаптеры сама.
- **NFR-5. Один источник настройки.** Компонент определяет настройку и её значение по умолчанию; правка хранится у него же. Приоритет: экспериментальный запрос, пользовательская правка, значение по умолчанию. Новые серверные настройки появляются в интерфейсе из описания сервера.
- **NFR-6. Задержка — предложение.** Сокращать ожидание после стопа; числовую цель выбрать после замеров на поддерживаемых моделях.
- **NFR-7. Память.** Одновременно работает одна модель. Выгрузка при простое пока не решена.
- **NFR-8. Фокус — предложение.** Запись и индикатор не должны мешать работе. Сейчас возврат к исходному полю может вывести его приложение на передний план; это нужно учитывать в дальнейшем дизайне.
- **NFR-9. Восстановление результата — предложение.** Если вставка не удалась, дать скопировать текст. Сейчас есть буфер обмена; история ещё не реализована. Не сохранять приватные результаты ради восстановления.
- **NFR-10. Объём данных — предложение.** Хранить только нужное для разбора и обучения. Объяснять, что записи содержат контекст разговора и могут попадать в резервные копии.
- **NFR-11. Доверие перед выпуском.** Проверяемый исходный код, подпись и нотаризация; сетевые обращения только для явно заявленных функций. Публичное открытие репозитория ещё не выполнено.
- **NFR-12. Один способ задания значения.** Конфиг хранит настройки у их компонентов. Выключатель — отдельное поле, а не особое значение бюджета. `--config` выбирает файл, но не вводит второй набор настроек.
- **NFR-13. Понятные подписи.** Название объясняет, что меняется. Короткая справка нужна, только если названия недостаточно. Значение по умолчанию видно в поле; допустимый диапазон — в сообщении об ошибке. Английский должен быть естественным и понятным без знания кода.
- **NFR-14. Без телеметрии.** Приложение и встроенные зависимости не отправляют аналитику, метрики или идентификаторы. Сейчас внешние соединения нужны только для запрошенной загрузки модели. Будущий механизм обновлений нужно описать и проверить отдельно.
