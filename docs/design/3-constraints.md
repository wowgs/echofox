# 3. Constraints

То, что задано снаружи и проектом не выбирается. У каждого пункта указано, откуда он известен.

## Платформа и оборудование (факт)

- macOS. Разработка и все замеры — на одном Маке: Apple M5 (10 ядер GPU), 24 ГБ памяти, macOS 27.0.1.
- Модель работает в llama.cpp (`llama-server` 0.6.0, сборка 11429, коммит `d81235049`, Homebrew) с Metal и общей памятью CPU и GPU.
- Файлы модели: Q8\_0 8,0 ГБ, Q4\_0 4,6 ГБ, аудиопроектор BF16 0,99 ГБ (в папке моделей, `gemma-4-E4B-it-GGUF/`).
- Память `llama-server` с Q8\_0 (`vmmap`, 2026-10-19): веса отображены из файла (mmap), 7,6 ГБ, сразу после запуска 7,5 ГБ из них в RAM; эти страницы чистые, macOS при нехватке памяти отбрасывает их и перечитывает с диска. Своей памяти у процесса после запуска 0,66 ГБ. С кэшем промптов по умолчанию (`--cache-ram` 8192 МиБ) она за 27 часов выросла до 8,85 ГБ и ушла в swap; поэтому кэш выключен (`--cache-ram 0`).
- На этом Маке памяти мало: 2026-10-19 было занято 23 ГБ из 24, swap — 9,2 ГБ из 10.

## Модель (факт)

- Gemma 4 принимает не больше 30 с звука за один запрос, 25 токенов на секунду (карточка модели). Длинная запись режется на куски.
- llama.cpp сам пишет в журнал, что вход звука у него экспериментальный.
- Ответ модели на кусок ограничен, иначе модель может не остановиться (лимит токенов на секунду звука, `server/dictation.py`).
- На тишине модель не возвращает пустой текст: она пишет текст от себя или копирует контекст разговора. В 2038 сохранённых кусках (2026-10-15 — 2026-10-22) так было у всех 35 кусков, где Silero VAD нашёл 0–0,06 с речи.
- Генерация упирается в чтение памяти: на каждый токен модель читает все веса. Медиана — 21 токен в секунду; генерация — 78% времени от стопа до текста в записях из одного куска (метрики 2026-10-18 — 2026-10-19).

## macOS (факт, по документации Apple)

- Запись с микрофона и вставка текста в чужие приложения требуют согласия пользователя: разрешения «Микрофон» и «Универсальный доступ».
- Элемент с курсором и вставку даёт Accessibility (`kAXFocusedUIElementAttribute`, `kAXSelectedTextAttribute`). Приложения на Electron отдают дерево только после `AXManualAccessibility = true` (замер на Claude Desktop, 2026-10-15). Позицию текстового курсора (`AXBoundsForRange`) ни Claude Desktop, ни Telegram, ни Ghostty в замере не отдали (вкладка 4).

## Целевые приложения (факт)

- Claude Desktop подписан Anthropic, Electron проверяет целостность `app.asar`; код диктовки приходит с claude.ai. Патчить его нечем и нельзя — отсюда диктовка на уровне ОС.
- Разговоры Claude Code (Desktop, расширение VS Code, CLI) лежат в `~/.claude/projects/<проект>/<id>.jsonl`; поле `entrypoint` говорит, из какого клиента пришла строка. Какая сессия сейчас на экране, из этих файлов не видно.
- Codex Desktop (`com.openai.codex`) не включает дерево Accessibility по `AXManualAccessibility` (ошибка −25205, 2026-10-18): поле ввода и URL из него не прочитать.

## Распространение (проверить)

- Подпись и нотаризация: чтобы скачанное приложение запускалось без предупреждений macOS, нужна подпись Developer ID и нотаризация Apple. Это по памяти, не проверено по документации Apple. Сертификатов подписи на Маке нет (факт, 2026-10-15).
- Условия использования Gemma для скачивания модели из приложения и для публичного продукта — не проверены.
