# 2. One recording, step by step

Пример: запись на 50 секунд с выбранной моделью «Gemma E4B llama.cpp». Нарезка — по настройкам сервера (`pieceSeconds` 20, `cutSearchSeconds` 3).

## Что происходит

1. **Старт записи.** Клиент открывает WebSocket к `ws://127.0.0.1:8090` и отправляет `start`: имя модели, язык и id сессий Claude Code или приложение с полем ввода. Промпт и `options` модели сервер берёт из своего реестра. Сервер заводит папку записи и пишет туда `mic.wav` по мере записи. Захват микрофона начинается сразу, звук идёт на сервер кусочками.
2. **История чата.** Пока ты говоришь, сервер читает JSONL самой свежей из этих сессий (или самой свежей сессии приложения): только мои итоговые ответы (последний текст каждого завершённого хода, `stop_reason: end_turn`) и английские термины из них. Твоих сообщений там нет: модель переписывала твою прошлую диктовку вместо того, чтобы расшифровать новую (запись `161929`, 14 октября). Моих промежуточных текстов между вызовами инструментов тоже нет.
3. **Текст перед звуком.** Пока ты говоришь, сервер берёт самые новые сообщения, которые помещаются в `chatHistoryTokenBudget` (у выбранной модели 2000 токенов), термины в десятую часть бюджета и твой промпт. Токены считает `llama-server` (`/tokenize`).
4. **Остановка.** Ты останавливаешь запись, клиент отправляет `stop`. Пока ты говорил, звук только копился, и сервер считал его громкость.
5. **Нарезка.** Теперь длина записи известна. Сервер делит её на столько равных кусков, чтобы они были ближе всего к 20 с и не длиннее 30 с: 25 с — один кусок, 44 с — два по 22, 62 с — три по 20,7. Каждый разрез сдвигается в самую тихую паузу в пределах 3 с от точки равного деления.
6. **Куски.** Каждый кусок — отдельный запрос к `llama-server`: текст перед звуком и звук только этого куска. Текст у всех кусков один, и `llama-server` держит его в кэше между запросами (`cache_prompt`). Прошлых ответов модель не видит, поэтому не повторяет их (вкладка 3). Тексты приходят по порядку, потом `done`.
7. **Уровни и запись.** Сервер дописывает `adapter.json` (текст, причина остановки, сессия, микрофон) и пишет в `audio.json` громкость речи и фона, пик, перегруз, самый длинный участок цифровой тишины (нули — признак закрытого или выключенного микрофона) и громкость по секундам, а при перегрузе или нулях пишет предупреждение в лог.

Ответ модели на один кусок ограничен 10 токенами на секунду звука плюс 32. Это защищает от зацикливания, например на нулях.
