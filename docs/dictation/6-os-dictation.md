# 5. Dictation at the OS level

Проект на 15 октября 2026: диктовка нашей моделью в любом приложении macOS, в том числе в Claude Desktop, без вмешательства в само приложение. Ничего ещё не сделано. Что при этом чистится и переделывается в сервере и в патче VS Code — вкладка «6. Cleanup and refactoring».

## Цель

По горячей клавише наше приложение пишет звук, отправляет его на наш сервер и вставляет текст туда, где стоял курсор. Выбор модели и настройки живут в приложении в строке меню.

## Решения Алекса

- Claude Desktop не трогаем: ни файлы приложения, ни его трафик, ни протокол и авторизацию Anthropic. Только системные API macOS: свой захват звука, горячая клавиша, Accessibility (14 октября).
- Основной режим — горячая клавиша и вставка через Accessibility. Режим «следовать за кнопкой микрофона Desktop» — дополнительная опция (15 октября).
- Клавиша — переключатель: нажал — запись, нажал ещё раз — стоп. Удержания нет (15 октября).
- Вставку через Accessibility считаем рабочей, раз её допускает документация Apple. Если поле за время ожидания исчезло или не приняло текст, это забота пользователя, а не приложения (15 октября).

## Почему не патч самого Desktop (факты)

- Claude Desktop 2.37337.1 подписан Anthropic (Team ID `Q6L2SF6YDW`), в `Info.plist` есть `ElectronAsarIntegrity`: Electron сверяет `app.asar` с хешем.
- В `app.asar` нет кода диктовки: нет `getUserMedia`, нет адресов `voice_stream` и `speech_to_text`. Есть маршруты `/code/…` на `https://claude.ai`, а документация Desktop пишет, что код приложения грузится с CDN Anthropic. Вывод (не проверен в работе приложения): интерфейс Code и его диктовка приходят с claude.ai, на диске патчить нечего.
- Local-сессии Desktop пишут транскрипт туда же, куда другие клиенты Claude Code: `~/.claude/projects/<проект>/<id>.jsonl`, с `"entrypoint":"claude-desktop"`. Проверено на сессии, которую перенесли из VS Code в Desktop: тот же файл, 103 строки от `claude-vscode` и 47 от `claude-desktop`.

## Части приложения

1. **Горячая клавиша.** Глобальная, переключатель. При старте записи запоминает поле с курсором: `kAXFocusedUIElementAttribute` у системного элемента (`AXUIElementCreateSystemWide`) и приложение, которому оно принадлежит.
2. **Запись.** Микрофон через AVAudioEngine, перевод в 16 кГц, 16 бит, моно, кусками по мере записи на сервер.
3. **Клиент сервера.** WebSocket к `gemma_voice.py`, протокол уже есть (README, раздел о протоколе): `start` с именем модели, языком и `app` — bundle id приложения, где стоял курсор; звук; `stop` с причиной. В ответ признаки речи, текст по кускам, `done`. Контекст чата и всю запись (`mic.wav`, `adapter.json`) сервер ведёт сам, приложению их делать не нужно.
4. **Вставка.** После `done` пишет текст в запомненное поле через `AXUIElementSetAttributeValue` (атрибут `kAXSelectedTextAttribute`: текст встаёт на место курсора или выделения).
5. **Меню в строке меню.** Модель, язык, остановка после тишины, ссылка на `~/.local-voice/config.json`, статус: «ожидание», «идёт запись», «ждём модель», «ошибка» с текстом ошибки.

## Одна запись

1. Курсор стоит в поле ввода, ты жмёшь клавишу. Приложение запоминает поле, начинает запись и открывает соединение с сервером. Статус: «идёт запись».
2. Звук идёт на сервер по ходу записи.
3. Ты жмёшь клавишу ещё раз, или сервер не слышит речи дольше, чем задано в «остановке после тишины». Приложение шлёт `stop`. Статус: «ждём модель».
4. Сервер присылает текст по кускам и `done`; ожидание до 180 с.
5. Приложение вставляет весь текст в запомненное поле. Статус: «ожидание». Если вставка не удалась — статус «ошибка»; текст остаётся в папке записи.

## Что упрощается по сравнению с опцией «кнопка Desktop»

- Не нужен детектор чужой записи: запись начинает и кончает сама горячая клавиша.
- Не нужен параллельный захват: микрофон пишет только наше приложение.
- Нечего заменять: диктовка Anthropic не запускается, текст только вставляется.
- Работает одинаково в Claude Desktop, VS Code, терминале и других приложениях.

## Опция: следовать за кнопкой микрофона Desktop

Ты пользуешься кнопкой микрофона в Desktop. Приложение видит, что процесс Claude начал писать микрофон, параллельно пишет тот же микрофон, а после остановки заменяет текст, который вставила диктовка Anthropic, текстом нашей модели. Звук при этом уходит и в Anthropic. Сверх основного режима нужно: детектор записи через CoreAudio (`kAudioHardwarePropertyProcessObjectList`, `kAudioProcessPropertyPID`, `kAudioProcessPropertyIsRunningInput`), параллельный захват и поиск в поле участка, который вставил Anthropic. Делается после основного режима, если понадобится.

## Как собрать (предложение)

- Своё приложение на Swift в папке `macos/` этого репозитория: AppKit для меню, AVAudioEngine для звука, `URLSessionWebSocketTask` для сервера, AX API для вставки. Одно приложение — одна запись в разрешениях macOS: «Микрофон» и «Универсальный доступ».
- Подписывать постоянным сертификатом, а не ad-hoc (предположение, не проверено: разрешения macOS привязаны к подписи, и при ad-hoc-подписи каждая пересборка может сбрасывать «Универсальный доступ»).
- Запускается при входе в систему агентом launchd, как сервер.
- Альтернатива — Hammerspoon (`hs.hotkey`, `hs.menubar`, `hs.axuielement`) с записью звука внешним процессом (sox или ffmpeg). Хватит ли его, не проверено.

## Проверить

- Какой API горячей клавиши не требует разрешения «Мониторинг ввода».
- Сколько времени проходит от нажатия до начала записи, то есть не теряется ли начало фразы.

## Открытые вопросы

- Какая комбинация клавиш.
- Нажатие клавиши, пока ждём модель: начать новую запись (сервер поставит её в очередь за текущей) или ничего не делать.
- Swift или Hammerspoon.
- Как узнать сессию Claude, которая на экране. Сейчас по `app` сервер берёт самую свежую сессию этого приложения. 15 октября для Claude Desktop он взял другую сессию Desktop, которая работала параллельно, а не ту, что была на экране.
