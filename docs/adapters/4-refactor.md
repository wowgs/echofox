# 4. Что переделать (решение Алекса, 15 октября)

## Сервер

- Реестр адаптеров вместо списка в коде: встроенные плюс найденные в папке плагинов; грузятся только включённые в конфиге; плагин, который не прошёл базовую проверку (манифест, версия интерфейса, класс `Adapter`), не грузится, а в настройках сказано почему.
- Без включённых адаптеров `context` не вызывается вовсе: текст перед звуком — только промпт.
- Метрики и `adapter.json` записи: какой адаптер, версия плагина.

## Приложение

- Снимок фокуса и включение дерева Electron — только для приложений включённых адаптеров (сейчас дерево включается у любого Electron-приложения, которое стало активным: VS Code, Slack и другие тратят на него ресурсы зря). Включать при запуске такого приложения и при старте Local Voice; при активации — как страховку (повторное включение стоит 0,45 мс, медиана 20 прогонов, Claude Desktop, 15 октября).
- Раздел «Адаптеры» в окне настроек — вместе с новым UI, позже. Пока в меню строка «Adapters: …» и ошибки плагинов.

## Конфиг

- `adapters: {"<имя>": {"enabled": bool}}`.
- Версия конфига растёт до 3; сервер переводит версию 2 сам, при старте: включает встроенные адаптеры, чтобы у тех, кто уже пользовался, ничего не пропало. В новом конфиге адаптеров нет — базовый режим.

## Документы

- Основной документ: требования (базовый режим, необязательные адаптеры, плагины), HLD (слой адаптеров, разрешения) — когда решения здесь устоятся.

## Порядок

2. Плагины из папки, манифест, перезагрузка плагинов при изменении их файлов. Сделано 15 октября: встроенные плагины — `server/plugins/claude-desktop` и `server/plugins/claude-code`, загрузчик — `server/adapters/registry.py`; приложение спрашивает у сервера включённые адаптеры (`{"type": "adapters"}`). Установка по ссылке на GitHub — вместе с новым UI.
